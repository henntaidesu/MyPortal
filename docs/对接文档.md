# 接入门户单点登录（SSO）对接文档

面向要接入门户的业务系统开发者。读完能做到：用户在门户点一张卡片，直接进你的系统，
不用再输一次账号密码；在门户点退出，你的系统里的会话也跟着失效。

对接工作量很小——**你只需要写两个接口**，一个接收跳转、一个接收登出通知。

---

## 1. 先理解这套流程

门户和你的系统不在同一个域名下，Cookie 天然带不过去。所以用的是 CAS 风格的
**一次性票据**：URL 里只出现一张 60 秒过期、用一次就作废的票，真正的身份数据走
**服务端到服务端**的 HTTP，中间不经过浏览器。

```
浏览器                     门户 / 认证中心                你的系统
  │                              │                              │
  │ 点门户上的卡片               │                              │
  ├─ GET /sso/authorize ────────▶│                              │
  │      ?client_id=crm          │ 有门户会话吗？               │
  │                              │  没有 → 跳登录页，登完再回来 │
  │                              │  有   → 签一张票（60 秒）    │
  │◀── 302 你的回调地址?ticket=ST-xxx ───────────────────────────│
  │                              │                              │
  ├─ GET 你的回调地址?ticket=ST-xxx ───────────────────────────▶│
  │                              │◀── POST /sso/validate ───────┤ 后端对后端
  │                              │     client_id+secret+ticket  │ 浏览器看不到
  │                              ├── 用户信息 ─────────────────▶│
  │                              │                              │ 建你自己的会话
  │◀── 302 你的首页 + 你自己的 Cookie ───────────────────────────│
  │                              │                              │
  └─ 进系统，一次密码都没输过                                     │
```

关键点：**票据本身不是身份**。它只是一个一次性的兑换凭证，必须由你的**后端**拿着
`client_secret` 去换，换到的才是用户信息。票据在 URL 里裸奔没关系——它 60 秒过期、
只能用一次、而且绑死了你的 `client_id`。

### 名词

| 名词 | 是什么 | 谁持有 |
| --- | --- | --- |
| `client_id` | 你的系统在门户里的唯一标识，比如 `crm` | 公开，可以出现在 URL 里 |
| `client_secret` | 你的系统换身份用的密钥 | **只能待在你的服务端** |
| `ticket` | 一次性票据，形如 `ST-xxxxx`，60 秒过期 | 经浏览器传递，用完即废 |
| `sid` | 门户会话编号，形如 `s-xxxxx` | 你存下来，用于单点登出 |
| `redirect_uri` | 你的回调地址，必须提前登记 | 精确匹配，一字不差 |
| `logout_uri` | 你接收登出通知的地址 | 可选，但建议做 |
| `home_url` | 你的系统首页，登出后回跳用 | 可选 |

---

## 2. 第 0 步：找门户管理员注册你的系统

**这一步不是你做的**，把下面的信息给门户管理员，他在门户服务器上执行注册命令：

需要提供四项：

- 一个 `client_id`，英文短标识，比如 `crm`、`oa`、`wiki`
- 系统显示名，会出现在门户的下拉框里，比如「客户管理系统」
- **回调地址**（`redirect_uri`）：你系统里接收跳转的完整地址
- **登出通知地址**（`logout_uri`）：你系统里接收登出广播的完整地址，可选

管理员执行：

```bash
cd backend
python manage.py addclient crm --name "客户管理系统" \
    --redirect-uri http://192.168.1.20:8080/sso/callback \
    --logout-uri  http://192.168.1.20:8080/sso/logout-notify \
    --home-url    http://192.168.1.20:8080/
```

命令会打印出 `client_id` 和 `client_secret`，管理员把这两个值给你。

> **回调地址必须一字不差。** 含协议、含端口、含路径，不能多一个斜杠。门户是精确匹配的，
> 不做前缀匹配——这是防止票据被诱导送到别人服务器的关键。
> 内网外网各一个地址？让管理员用多个 `--redirect-uri` 参数注册多条，都会进白名单。

拿到 `client_secret` 后，**把它放进你的服务端配置文件或环境变量，不要写进前端 JS，
不要提交进代码仓库**。

---

## 3. 第 1 步：没登录就去要票

用户直接访问你系统的任何页面时，如果你这边没有本地会话，就 302 跳到门户：

```
302 → {门户地址}/sso/authorize?client_id={你的client_id}&redirect_uri={你的回调地址}&state={随机串}
```

| 参数 | 必填 | 说明 |
| --- | --- | --- |
| `client_id` | 是 | 管理员给你的那个 |
| `redirect_uri` | 否 | 省略时用注册的第一条。注册了多条就要明确指定 |
| `state` | 否 | 原样带回来，用来防 CSRF，**强烈建议填** |

`state` 的正确用法：生成一个随机串，存进你自己的临时 Cookie 或 session，跳转时带上；
回调里比对，对不上就拒绝。这样别人没法拿一个自己的票据诱导你的用户完成登录。

用户如果还没登录门户，门户会先让他登录，登完自动跳回来，你这边无感。

---

## 4. 第 2 步：回调里拿票换身份

用户带着票回到你的系统：

```
GET {你的回调地址}?ticket=ST-xxxxx&state=xxxxx
```

在你的**后端**发一次请求换取身份：

```
POST {门户地址}/sso/validate
Content-Type: application/json

{
  "client_id": "crm",
  "client_secret": "管理员给你的密钥",
  "ticket": "ST-xxxxx"
}
```

> 也接受 `application/x-www-form-urlencoded` 表单，方便 PHP 和一些老框架。
> `client_secret` 字段也可以写成 `secret`，两个名字都认。

**成功返回 200：**

```json
{
  "ok": true,
  "user": {
    "username": "zhangsan",
    "display_name": "张三",
    "email": "zhangsan@example.com",
    "roles": ["admin", "ops"]
  },
  "sid": "s-xxxxxxxx",
  "session_expires_at": 1757000000.0
}
```

| 字段 | 说明 |
| --- | --- |
| `user.username` | 登录名，全局唯一，**拿它作为你系统里的用户标识** |
| `user.display_name` | 显示名，展示用 |
| `user.email` | 邮箱，可能为空字符串 |
| `user.roles` | 角色数组，门户里配的，原样透传，可能为空数组 |
| `sid` | 门户会话编号，**必须存下来**，第 3 步要用 |
| `session_expires_at` | 门户会话的过期时间戳（秒），可以拿来对齐你的会话时长 |

**失败返回 401**，body 是 `{"detail": "..."}`。注意：**失败原因不区分**——票据无效、已过期、
已经用过、`client_id` 对不上、`client_secret` 不对，全都是 401。这是故意的，不给探测留缝隙。

拿到 `user` 之后，按你系统原来的方式建会话（Session / JWT / 随便什么），**把 `sid` 一起存进
你的会话记录里**，下一步要靠它做登出联动。然后 302 回你的首页，流程结束。

### 这一步最容易做错的三件事

1. **不要在前端 JS 里调 `/sso/validate`。** 那样 `client_secret` 就公开了，任何人都能拿它换任意身份。
2. **票据只能换一次。** 换完就作废是门户保证的，你这边不用做去重；但也意味着你不能重试同一张票。
3. **用 `username` 做用户标识，不要用 `sid`。** `sid` 是会话编号，每次登录都不一样。

> **`username` 是会变的。** 门户管理员可以在「设置 → 用户管理」里给人改名，用户自己也能在
> 「设置 → 我的账号」里改。改完门户这边还是同一个人（内部按 id 认），
> 但你这边如果拿 `username` 当主键，就会当成一个新用户。所以：库里给用户表留一个能改的
> 登录名字段，别把它设成不可变的主键；线上真要改名时，两边一起改。

---

## 5. 第 3 步：接单点登出（可选，但建议做）

用户在门户点退出时，门户会向你注册的 `logout_uri` 发一个 POST：

```
POST {你的 logout_uri}
Content-Type: application/json

{
  "sid": "s-xxxxxxxx",
  "client_id": "crm",
  "secret": "你的 client_secret",
  "nonce": "随机串"
}
```

你要做两件事：

1. **先校验 `secret`**，用定长比较函数（PHP 的 `hash_equals`、Node 的 `crypto.timingSafeEqual`、
   Python 的 `hmac.compare_digest`），不要用 `==`。校验不过直接返回 401。
2. 把你系统里所有「记录的 `sid` 等于这个 `sid`」的本地会话删掉。

返回什么门户不关心，200 就行。

这个通知是**尽力而为**的：你的系统挂了不影响门户退出，只是你这边的会话会一直活到自己设的
过期时间。不做这一步也能跑，只是退出不彻底。

### 反过来：从你的系统退出门户

你系统里的「退出」如果想把门户和其他系统一起退掉，跳转到：

```
302 → {门户地址}/sso/logout?client_id={你的client_id}
```

退完会自动回到注册时填的 `home_url`。

> 注意这个接口**不接受调用方自带回跳地址**，只认注册时登记的 `home_url`。
> 登出接口是最容易被做成开放重定向的地方，所以门户这边把口子焊死了。

## 6. 接口速查

门户地址记作 `{SSO_BASE}`，比如 `http://192.168.1.10:9920`。

### GET /sso/authorize

浏览器跳转用。

| 参数 | 必填 | 说明 |
| --- | --- | --- |
| `client_id` | 是 | 你的标识 |
| `redirect_uri` | 否 | 省略用注册的第一条；传了就必须在白名单里 |
| `state` | 否 | 原样带回 |

响应：302 到 `{redirect_uri}?ticket=ST-xxx&state=xxx`。
出错时不跳转，直接返回一个说明问题的 HTML 页面（未注册的 client_id、回调地址不在白名单）。

### POST /sso/validate

服务端到服务端，换身份用。请求体见第 4 步，JSON 和表单都收。

- 200：`{"ok": true, "user": {...}, "sid": "...", "session_expires_at": ...}`
- 401：`{"detail": "..."}`，原因不区分

### GET /sso/logout

浏览器跳转用。参数 `client_id`（可选）。响应 302 到该 client 注册的 `home_url`，没有就回门户首页。

---

## 7. 几条不要省的红线

- **`client_secret` 只能待在服务端。** 进了前端 JS 或代码仓库，任何人都能拿它换任意用户的身份。
- **`redirect_uri` 由门户精确匹配。** 你这边也不要做「拿 URL 参数当回调地址」这种设计。
- **`state` 要校验。** 生成、存起来、回调时比对，不比对等于没做 CSRF 防护。
- **`secret` 用定长比较。** `==` 会泄露比较进度，给时序攻击留缝隙。
- **别拿 `sid` 当身份凭证。** 它只是会话编号，用于登出联动；绝不要接受浏览器传来的 `sid`
  直接登录某个用户。
- **生产环境走 https。** 票据虽然是一次性的，但 60 秒窗口内明文传输仍然不理想。

---

## 8. 对不上的时候怎么查

| 现象 | 多半是 |
| --- | --- |
| 跳转后显示「回调地址未登记」 | 你传的 `redirect_uri` 和注册的不一字不差。查端口、查末尾斜杠、查 http/https |
| 跳转后显示「未注册的系统」 | `client_id` 拼错，或者管理员还没注册 |
| `/sso/validate` 返回 401 | 票过期了（超过 60 秒）、票用过了、`client_secret` 不对。注意别重试同一张票 |
| 一直在门户和你的系统之间来回跳 | 你的回调里建会话失败了，回到首页又判定没登录，再次跳门户。先把建会话那段日志打出来 |
| 门户退出了，你的系统还在登录态 | `logout_uri` 没注册，或者你没存 `sid`，或者 `secret` 校验没过 |
| 登录成功但立刻又变未登录 | 你自己的 Cookie 设了 `Secure` 但跑在 http 下，浏览器会直接丢弃 |

---

## 9. 最小实现骨架

语言无关的伪代码，两个接口就是全部：

```
# 接口一：回调
GET /sso/callback:
    ticket = query["ticket"]
    if query["state"] != 我存的state: 拒绝

    resp = HTTP_POST("{SSO_BASE}/sso/validate", json={
        "client_id": CLIENT_ID,
        "client_secret": CLIENT_SECRET,     # 从服务端配置读，不是硬编码
        "ticket": ticket,
    })
    if resp.status != 200: 显示登录失败, 结束

    user = resp.json["user"]
    本地会话 = 建会话(username=user["username"], roles=user["roles"])
    本地会话.sso_sid = resp.json["sid"]      # 存下来，登出要用
    302 到首页

# 接口二：接收登出通知
POST /sso/logout-notify:
    body = 读JSON或表单
    if not 定长比较(body["secret"], CLIENT_SECRET): 返回 401
    删除所有 sso_sid == body["sid"] 的本地会话
    返回 200
```

换身份那次请求，几种语言的关键写法：

```python
# Python
import httpx
r = httpx.post(f'{SSO_BASE}/sso/validate', json={
    'client_id': CLIENT_ID, 'client_secret': CLIENT_SECRET, 'ticket': ticket}, timeout=5)
user = r.json()['user'] if r.status_code == 200 else None
```

```javascript
// Node
const r = await fetch(`${SSO_BASE}/sso/validate`, {
  method: 'POST',
  headers: { 'content-type': 'application/json' },
  body: JSON.stringify({ client_id: CLIENT_ID, client_secret: CLIENT_SECRET, ticket }),
})
const user = r.ok ? (await r.json()).user : null
```

```php
// PHP：表单方式，不用装任何扩展
$body = http_build_query(['client_id' => CLIENT_ID,
                          'client_secret' => CLIENT_SECRET, 'ticket' => $ticket]);
$ctx = stream_context_create(['http' => [
    'method' => 'POST', 'timeout' => 5,
    'header' => "Content-Type: application/x-www-form-urlencoded\r\n",
    'content' => $body, 'ignore_errors' => true]]);
$raw = file_get_contents(SSO_BASE . '/sso/validate', false, $ctx);
$user = $raw ? (json_decode($raw, true)['user'] ?? null) : null;
```

```java
// Java 11+
var req = HttpRequest.newBuilder(URI.create(SSO_BASE + "/sso/validate"))
    .header("Content-Type", "application/json")
    .POST(HttpRequest.BodyPublishers.ofString(
        "{\"client_id\":\"" + CLIENT_ID + "\",\"client_secret\":\"" + CLIENT_SECRET
        + "\",\"ticket\":\"" + ticket + "\"}"))
    .build();
var resp = HttpClient.newHttpClient().send(req, HttpResponse.BodyHandlers.ofString());
```

对接过程中有疑问，或者需要改注册信息（换回调地址、加一条内网地址、重置 secret），
找门户管理员。
