# 门户单点登录对接文档

> 适用于：要接入门户（Portal）单点登录的系统的开发者，以及负责部署配置的人。
> 已接入：**FreeMarket Manager**（优先）、**R-18MediaLibrary（DL 媒体库）**。

## 1. 概述

门户充当 **OIDC 身份提供方（IdP）**，各系统充当客户端（RP）。用户在门户登录一次，
进其他系统时点「门户登录」就能直接进去，不用再输密码。

- 协议：OpenID Connect，**只支持授权码流程**（`response_type=code`），建议同时带 PKCE（S256）。
- id_token 签名：**HS256**，密钥是**该客户端自己的 `client_secret`**。客户端拿自己的 secret 就能验签，
  不需要 jwks。一个系统的 secret 泄露，伪造不出发给别的系统的 token。
- **两边都开才生效**：门户 `conf.json` 里登记这个系统；系统自己的「系统关联 · 单点登录」配置项打开。
  缺任何一边，登录页都不会出现按钮（或者点了被拒）。

### 登录时序

```
浏览器                    业务系统（RP）                      门户（IdP）
  │ 点「门户登录」             │                                  │
  │ ─────────────────────────>│ GET /…/sso/login?base=<本系统地址>   │
  │ <── 303 + 临时Cookie(state/nonce/PKCE) ─┤                     │
  │ ──────────────────────────────────────────────────────────────>│ GET /api/oidc/authorize
  │               （没登录门户 → 先进门户登录页，登录后自动跳回）       │
  │ <──────────────────── 303 redirect_uri?code=…&state=… ─────────┤
  │ ─────────────────────────>│ GET /…/sso/callback               │
  │                           │ ── POST /api/oidc/token（后端直连）─>│
  │                           │ <── id_token / access_token ───────┤
  │                           │ 验签 + 校验 iss/aud/exp/nonce        │
  │                           │ 按门户身份找/建本系统用户            │
  │ <── 303 回首页并建好会话 ────┤                                  │
```

## 2. 门户侧配置

编辑门户 `backend/conf.json`（打包版在 `Portal.exe` 同级目录），**改完重启门户**：

```json
"idp": {
  "enabled": true,
  "issuer": "https://portal.example.com",
  "clients": [
    {
      "client_id": "freemarket",
      "client_secret": "<至少 32 位随机串>",
      "name": "FreeMarket",
      "redirect_uris": [
        "https://freemm.makurochan.com/mercariV2/src/use_web/sso/callback",
        "https://fme.makurochan.com/mercariV2/src/use_web/sso/callback"
      ]
    },
    {
      "client_id": "dlsite-media",
      "client_secret": "<至少 32 位随机串>",
      "name": "DL媒体库",
      "redirect_uris": [
        "http://10.0.10.20:9800/api/sso/callback",
        "https://portal.example.com/api/proxy/mvqnbi1eoa/api/sso/callback"
      ]
    }
  ]
}
```

| 字段 | 说明 |
| --- | --- |
| `enabled` | 门户提供方总开关。关着时所有 `/api/oidc/*` 都返回 404 |
| `issuer` | **浏览器访问门户用的地址**，不带末尾 `/`。会写进 id_token 的 `iss`，各系统填的「门户地址」必须和它**一字不差**。留空就按请求的 Host 现拼，不推荐 |
| `client_id` | 系统的标识，两边填同一个值 |
| `client_secret` | 至少 32 个字符。生成方法：`python -c "import secrets;print(secrets.token_urlsafe(32))"` |
| `redirect_uris` | 回调地址，**逐字比对**。系统有几个访问地址（多个域名、局域网 IP、经门户代理）就登记几条 |

> 系统经门户「代理」卡片打开时，浏览器看到的地址是 `<门户>/api/proxy/<卡片 id>/…`，
> 所以回调地址也要按这个形状再登记一条。

## 3. 门户端点规格

以 `{issuer}` 指代门户地址。

### 3.1 发现文档 `GET {issuer}/.well-known/openid-configuration`

返回标准 OIDC 发现文档，其中 `issuer`、`authorization_endpoint`、`token_endpoint`、`userinfo_endpoint`
可以直接用。适合拿来做「测试连接」：取回后核对 `issuer` 和配置的门户地址是否一致。

### 3.2 授权 `GET {issuer}/api/oidc/authorize`（浏览器整页跳转）

| 参数 | 必填 | 说明 |
| --- | --- | --- |
| `response_type` | 是 | 固定 `code` |
| `client_id` | 是 | |
| `redirect_uri` | 是 | 必须在登记表里 |
| `scope` | 是 | 必须包含 `openid`，建议 `openid profile` |
| `state` | 建议 | 原样带回，用来防 CSRF |
| `nonce` | 建议 | 写进 id_token，用来防重放 |
| `code_challenge` / `code_challenge_method` | 建议 | PKCE，支持 `S256`（推荐）和 `plain` |

行为：

- `client_id` 不存在、或者 `redirect_uri` 没登记 → **停在门户显示错误页，不会跳回去**。
- 用户没登录门户 → 先去门户登录页，登录成功后自动继续授权。
- 其他参数错误 → 303 回 `redirect_uri?error=…&error_description=…&state=…`。
- 成功 → 303 回 `redirect_uri?code=…&state=…`。授权码 **60 秒内有效、只能用一次**。

### 3.3 换 token `POST {issuer}/api/oidc/token`（后端调用）

`Content-Type: application/x-www-form-urlencoded`

| 参数 | 说明 |
| --- | --- |
| `grant_type` | 固定 `authorization_code` |
| `code` | 回调拿到的授权码 |
| `redirect_uri` | 必须和授权时的完全一致 |
| `code_verifier` | 授权时带了 PKCE 才需要 |
| `client_id` / `client_secret` | 放表单里（client_secret_post），或者用 `Authorization: Basic`（client_secret_basic） |

成功返回 `200`：

```json
{
  "access_token": "…",
  "token_type": "Bearer",
  "expires_in": 3600,
  "scope": "openid profile",
  "id_token": "<JWT>"
}
```

失败返回 `400 / 401` + `{"error": "...", "error_description": "..."}`，`error` 取值有
`invalid_client`（secret 不对）、`invalid_grant`（码无效 / 已用过 / 已过期 / redirect_uri 不一致 / PKCE 不对）、
`unsupported_grant_type`。授权码不论成败都**当场作废**。

### 3.4 用户信息 `GET {issuer}/api/oidc/userinfo`

请求头带 `Authorization: Bearer <access_token>`，返回和 id_token 一样的用户字段。
门户里改密码、停用账号、踢下线之后，旧的 access_token 会立刻失效（返回 401）。
id_token 里已经带齐资料，一般用不到这个接口。

### 3.5 id_token 内容

```json
{
  "iss": "https://portal.example.com",
  "aud": "freemarket",
  "sub": "7",
  "iat": 1761300000,
  "exp": 1761303600,
  "nonce": "…",
  "preferred_username": "makuro",
  "name": "显示名",
  "groups": ["admin"]
}
```

| claim | 含义 |
| --- | --- |
| `sub` | **门户用户 id（字符串）**。认人只认它，门户里改用户名也不会变 |
| `preferred_username` | 门户用户名。只在首次匹配 / 新建用户时使用 |
| `name` | 显示名 |
| `groups` | 门户管理员是 `["admin"]`，其余是 `[]`。各系统**自行决定**要不要据此授予权限（FreeMarket、DL 媒体库都不据此提权） |

**客户端必须校验**：HS256 签名（用 client_secret）、`iss` = 配置的门户地址、`aud` = 自己的 client_id、
`exp` 未过期、`nonce` = 本次发出的值。

## 4. 接入方需要实现的内容

### 4.1 配置项（「系统关联 · 门户单点登录」）

每个系统都要有自己的配置项，**打开且填齐才启用**：

| 配置项 | 说明 |
| --- | --- |
| 启用 | 关着时登录页不显示按钮，单点登录相关接口一律 404 |
| 门户地址 | = 门户 `idp.issuer` |
| 门户内网地址（可选） | 后端换 token 用的地址，比如 `http://10.0.10.5:9921`。门户挂在 Cloudflare 等后面时，直连内网更稳。留空就用门户地址 |
| Client ID / Client Secret | = 门户登记的值。Secret 只写不读，界面上不回显明文 |

### 4.2 接口

| 接口 | 作用 |
| --- | --- |
| `GET …/sso/login?base=<本系统地址>` | 生成 state / nonce / PKCE，存进签名过的临时 Cookie（`HttpOnly; SameSite=Lax`，10 分钟），然后 303 去门户授权 |
| `GET …/sso/callback` | 校验 state → 换 token → 验 id_token → 匹配用户 → 建会话 → 回首页。出错就回登录页并带上原因 |
| 登录页状态接口 | 告诉前端要不要显示「门户登录」按钮 |

**`base` 由浏览器提供**（页面所在地址），回调地址 = `base + 回调路径`。
系统可能有多个域名，或者经门户代理打开，后端从请求头不一定猜得准。门户会逐字比对登记表，
所以 base 交给浏览器给也是安全的。

临时 Cookie 的 `SameSite` **必须是 Lax**：从门户跳回来是一次跨站的顶层导航，设成 Strict 浏览器就不会带上它。

### 4.3 校验双方用户名（用户匹配规则）

两个已接入系统都按这套规则：

1. 用 `sub` 找已绑定的本地用户 → 找到就用这个用户登录。
2. 没绑定过 → 用 `preferred_username` 找本地同名用户（不区分大小写）→ 找到就绑定。
3. 本地没有这个用户 → **自动新建一个**（可配置为不自动建，改成拒绝登录）。
4. 同名本地用户已经绑定了**另一个**门户账号 → **拒绝登录，不自动改绑**。
   管理员在本系统里解绑（或删掉该用户）后，重新登录即可。

## 5. 各系统接入说明

### 5.1 FreeMarket Manager

- **配置位置**：系统设置 → 基础设置 → **系统关联 · 门户单点登录**（仅管理员可见）。
  - 配置项：启用开关、门户地址、门户内网地址、Client ID、Client Secret、
    没有同名用户时自动创建、新用户默认角色、登录页按钮文案。
  - 「测试连接」：读取门户的发现文档并核对地址。
  - 页面底部显示「门户 redirect_uris 需登记：…」，复制这个地址到门户 conf.json 即可。
  - 下方表格列出所有已绑定的门户账号，可以解绑（只删绑定关系，不删用户）。
- **回调地址**：`<FreeMarket 地址>/mercariV2/src/use_web/sso/callback`，每个访问域名各登记一条。
- **接口**（公开，不需要登录）：`/mercariV2/src/use_web/sso/{status,login,callback,exchange}`；
  配置接口：`/mercariV2/src/use_web/system/sso/{config,test,bindings}`（仅管理员）。
- **登录结果**：回调后跳到 `#/login?sso_ticket=…`，前端用这张**一次性票（60 秒）**换回和密码登录
  完全相同的 `{token, user}`。不直接把 JWT 放进地址，因为 FreeMarket 的 JWT 默认永不过期，
  放进地址栏会被浏览器历史和 nginx 日志记下来。
- **自动新建的用户**：不能用密码登录（需要管理员在账号管理里重置密码后才能用），不是管理员，
  按「新用户默认角色」分配页面权限。不选角色的话就是「未分配角色 = 不限制页面」，注意这一点。
- **用户名不跟着门户改**：FreeMarket 的用户名同时是密码登录的登录名，所以门户里改了名，
  这边只更新绑定记录，不改用户名。
- **数据**：新增表 `sso_identities`（启动时自动建，只建表、不改已有表）；配置存在 `config` 表的
  `portal_sso_*` 键。

### 5.2 R-18MediaLibrary（DL 媒体库，外部访问 Web 端）

- **配置位置**：桌面端 系统设置 → **门户单点登录**。
- **回调地址**：`http://<本机IP>:<端口>/api/sso/callback`；经门户代理访问时，再加一条
  `<门户>/api/proxy/<卡片 id>/api/sso/callback`。
- 单点登录开启后，Web 端**必须登录**（即使访问密码为空）。
- 门户里改了用户名，这边的用户名会跟着改（新名字已被别人占用时保留原名）。

## 6. 排错

| 现象 | 原因 / 处理 |
| --- | --- |
| 登录页没有「门户登录」按钮 | 本系统的单点登录没开，或者门户地址 / Client ID / Secret 没填齐 |
| 门户页面显示「回调地址 … 没有登记」 | 把提示里的地址原样加进门户 conf.json 的 `redirect_uris`，然后重启门户 |
| 门户页面显示「没有登记 client_id」 | 两边的 client_id 不一致，或者门户改完 conf.json 没重启 |
| 「id_token 的签发方 … 对不上」 | 本系统填的门户地址和门户 `idp.issuer` 不一致（注意 http/https、端口、末尾 `/`） |
| 「签名校验不过」「门户拒绝换 token（401）」 | 两边的 Client Secret 不一致 |
| 「连不上门户」 | 本系统后端访问不到门户：填「门户内网地址」，或者检查防火墙 |
| 「登录状态丢了 / 已过期」 | 临时 Cookie 没带回来：从点按钮到回来超过了 10 分钟，或者浏览器拦截了 Cookie |
| 「已绑定另一个门户账号」 | 见 4.3 第 4 条：在本系统里解绑后重新登录 |
| 门户启动时报 client_secret 太短 | 至少 32 个字符 |

## 7. 安全要点

- 门户对 `redirect_uri` 逐字比对；没登记的地址只会停在门户的错误页，不会把授权码送出去。
- 授权码 60 秒、只能用一次；带 PKCE 时还要校验 `code_verifier`。
- 门户里改密码 / 停用账号 / 踢下线，会让 access_token 立即失效。但**各系统已经建好的本地会话
  不受影响**，要靠各系统自己的会话管理（比如 FreeMarket 账号管理里的禁用 / 强制下线）。
- `client_secret` 只放在服务端：门户 conf.json 和各系统的配置存储里，不要下发给前端。
